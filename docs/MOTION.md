# 动效规范

这份文件是「下次改界面时不用重新争论」的结论，规则来自 Emil Kowalski 的动效原则
（[emilkowalski/skills](https://github.com/emilkowalski/skills)），落到本项目的 Compose 实现。

所有数值都在 `core/designsystem/motion/MeowMotion.kt`，组件只引用令牌，不写裸数字。

## 令牌

| 名称 | 值 | 用在哪 |
| --- | --- | --- |
| `easeOut` | `cubic-bezier(0.23, 1, 0.32, 1)` | 进入、退出、按压回弹。**默认就用它** |
| `easeInOut` | `cubic-bezier(0.77, 0, 0.175, 1)` | 元素在屏幕内位移 / 形变 |
| `drawer` | `cubic-bezier(0.32, 0.72, 0, 1)` | 底部弹层上滑 |
| `PRESS` | 120ms | 按压反馈 |
| `FAST` | 150ms | 高频状态切换（底栏高亮、胶囊选中） |
| `BASE` | 200ms | 通用过渡（进度、分段指示器、答案揭示） |
| `ENTER` / `EXIT` | 220ms / 180ms | 页面进入 / 退出（退出永远更快） |
| `SHEET` | 280ms | 弹层（唯一的 >250ms 例外） |

## 规则

1. **只动 `transform` 与 `opacity`**：按压缩放走 `graphicsLayer`，不触发布局。
   唯一的例外是手风琴式展开（编辑页填空答案区），高度动画在这里是必要的。
2. **绝不用 `ease-in`**：起步慢，用户等得最久的那一瞬正是最该响应的一瞬。
3. **绝不用 `scale(0)`**：元素从 0.95 左右 + 透明度淡入，现实里没有东西凭空长出来。
4. **UI 动效 < 300ms**，只有弹层到 280ms。
5. **按压必须有反馈**：本项目的卡片 / 胶囊 / 按钮都去掉了水波纹（`indication = null`），
   所以按压缩放是它们唯一的反馈信号，不能省。幅度 0.90–0.985，越大越廉价。
6. **高频操作不放位移**：底栏切页只做 150ms 交叉淡化；滑动切换会让每天几十次的操作变慢。
7. **不做逐项交错入场**：列表是滚动浏览的，逐项延迟会把「滑一下」变成「等它演完」。
   列表只在增删/移动时用 `Modifier.animateItem()`。
8. **空间关系要成立**：进详情页从右侧推入（1/5 屏），返回反向退出；推进时下层保持不动，
   两层同时位移会像在互相推挤。
9. **尊重系统设置**：`animator_duration_scale` 为 0（用户开启「移除动画」）时，
   所有动效退化为瞬间完成；0–1 之间按比例缩短。实现见 `LocalMotionScale`。

## 明确不做的

- 键盘 / 快捷键类动作不加动画（本 App 暂无）
- 列表滚动不做视差、不做淡入
- 不做装饰性的循环动画（呼吸、漂浮）
- 弹窗不开场放大到位移叠加的花活——它是居中模态，只做淡入 + 0.96 缩放
